# UNCAD Pro 2.6.4

发布日期：2026-10-11

本版修 U1U 批量更新的回滚保护漏洞、收敛 U1DWG 的事务范围，并把 BOQ 清单输出改到
CAD 提交之后（与 `docs/DEVELOPMENT.md` 一致）。

## 修复

**1. 批量更新偶发报"文件不属于当前回滚批次"（U1U）。**

批量路径用**计划侧**机台号建立回滚批次（`BatchFillUpdateCoordinator`），实际写盘路径却
来自**CAD 读出的**机台号（`AutomaticSubmissionService`）。D-021 规定机台号忽略内部空白
视为同一台、且保留原始文本，所以两边文本可能不同（例如图框属性 `MDAPT 01`、工作簿
`MDAPT01`）。这时写出的文件既没有备份也没有锁，回滚保护会漏掉它，用户先看到的是一句
没法照着做的"文件不属于当前回滚批次"。

现在 `FileBatchRollback.BeginWrite` 会把批次之外的输出路径**按需纳入保护**（建父目录 +
取锁 + 备份指纹），回滚覆盖真正写过的每个文件；`Find` 的报错也补上请求路径与批次已知
文件，便于用户照着查。同时"预期文件集"改为只拼路径不建目录，机台号写法变化不再留下
空的机台文件夹。

**2. DWG 导出把整个磁盘 IO 放在只读事务里（U1DWG）。**

以前整个导出——Wblock、SaveAs、大文件哈希、原子替换——都在一个只对源库只读的
`ctx.Db` 事务里跑：Commit 没有语义，却把只读事务与全部对象句柄持有到导出结束。
现在拆成"短只读事务读身份 + 无事务的导出阶段"，顺带修掉"事务内写注册表"
（输出目录解析里的 `Settings.Set` 不再处于事务中）。

## 变更

**BOQ 清单输出改到 CAD 提交之后（U1F/U1U，含批量）。**

以前 Excel 在 CAD 事务里、提交之前写：好处是 Excel 失败能连 CAD 一起回滚，代价是
"替换完成到 Commit 之间"崩溃会出现**新工程量表 + 旧图框**，而且与
`docs/DEVELOPMENT.md` 规定的顺序相反。

现在的顺序（与文档一致）：① 一个事务完成图框迁移、清单表、块属性与颜色并提交 →
② 提交后用短只读事务读取真实 CAD 结果并写 BOQ → ③ 读表会触发 AutoCAD 懒重算，
再用一个事务按固定行高回写一次（D-027）。

**失败语义（重要）**：②③ 失败时**不回滚已提交的图纸**，只把本批 BOQ 文件恢复为修改前的
版本，并在命令行与弹窗明确提示"图纸已更新，但 BOQ 输出失败；请重跑 `U1S` 重新导出清单"。
也就是说：图纸与 BOQ 不再保证"同生共死"，换来的是崩溃窗口里图纸永远是一个完整状态。
规范已同步写入 `docs/DEVELOPMENT.md`。

## 验证

- `dotnet test UNCAD.slnx`：1027 项全部通过（新增 3 项回滚保护回归测试；4 个"源码顺序"
  契约测试按新契约更新：加粗断言"BOQ 输出必须在 CAD 提交之后"）。
- 真机自检（accoreconsole）：`UNCAD_TABLE_FILL_SELFTEST` PASS、`UNCAD_U1Q_SELFTEST` PASS、
  `UNCAD_U1DWG_SELFTEST` PASS。

## 本次验证的限制（如实说明）

**没有覆盖 U1F/U1U 命令编排的真机自检**：现有 CAD 自检夹具需要完整图框 + 工作簿快照，
U1F/U1U 的编排一直靠契约测试与代码复核。因此"BOQ 输出移到提交之后"这条变更的真机验证
只到"表格写入 + 行高回写"这一层（`UNCAD_TABLE_FILL_SELFTEST` 正是这两步），
**编排层建议在下一次真机验收时专门跑一次 U1F 与 U1U**（含一次故意让 BOQ 目录只读，
确认提示确实是"图纸已更新，请重跑 U1S"）。

## 已核查但未改动

- `XFrameMigrationService` 在调用方写事务里读模板 DWG：模板仅 81KB、只在确实需要迁移时
  读取、且发生在任何图纸改动之前，收益不抵改动风险。
- `U1SET`/`U1DATA` 的授权门禁按用户答复（这两条命令使用频率低）暂不改动行为。
