# UNCAD Pro 2.6.1

发布日期：2026-10-11

## 修复一：命令行被重复提示刷屏

用户真机反馈：AutoCAD 命令行被同一条提示（例如一条维护通知公告）
一屏又一屏地重复刷出，无法正常看图。

根因是**通知取走后没有清空**：`OnlineLicenseMonitor.TryTakeNotice` 少了一句
`_pendingNotice = null`，而它在 `Bootstrap.OnLicenseIdle` 里被调用，
**AutoCAD 的 Idle 事件会持续触发**，于是同一条通知被无限次取出并写入命令行。
（同一文件里另一条 `TryTakeActivationRequest` 是清空的，这里漏了。）

修复后**一条通知只提示一次**。授权提示仍然只在命令行出现、不弹模态窗口，
不影响 AutoCAD 使用；需要登录时随时运行 `UNC_LOGIN`。

## 修复二：U1PDF 出图失败（eInvalidInput）→ 自研出图内核

2.6.0 的 U1PDF 在真机上出图失败，只回了一句 `eInvalidInput`。
现在改为**自研出图内核**（不依赖任何第三方批量打印插件 —— 第三方插件会接管
AutoCAD 界面、影响正在画图的人），并已在本机 AutoCAD 2022 上真机验证通过。

### 两个真正的根因（都是 AutoCAD 打印 API 的硬性约束）

1. **窗口区域必须先于打印范围类型设置**。
   先 `SetPlotType(Window)` 再 `SetPlotWindowArea` 会被 AutoCAD 以
   `eInvalidInput` 拒绝；必须反过来。2.6.0 失败的就是这一步。
2. **设备和介质必须设在布局自身的打印设置上**。
   用 `PlotInfo.OverrideSettings` 传一份独立的设置副本时，
   `PlotInfoValidator.Validate` 虽然返回通过，却把请求的 A3 介质
   **重新匹配成布局自带的 A4** —— 出图"成功"但纸张是错的。

### 现在的实现

- 出图前对布局打印设置拍完整快照，出图后**逐字段还原**，
  用户在"页面设置"里看到的纸张/比例/打印范围/打印样式表都不变。
- 显式指定规范介质：优选与图框横竖方向一致的 A3（其次 A4/A2/A1/A0），
  并优先挑不带 `full_bleed`/`expand` 的标准纸张；方向不一致时自动旋转 90°。
- 彩色：不套用打印样式表（保留图层颜色），并清空打印样式表名。
- 全程无对话框、无 `SendCommand`、不切布局、不缩放视图；出图只写命令行进度。
- 出图产物先校验 `%PDF-` 头 + `%%EOF` 尾 + 最小体积，半成品绝不上传。
- 失败时给出**逐步诊断**（第几步、哪个调用、`ErrorStatus`、当时的设备/介质/窗口），
  不再只有一个 `eInvalidInput`。

### 真机验证（AutoCAD 2022 + accoreconsole，`UNCAD_U1PDF_SELFTEST`）

- 横向 420×297 与纵向 297×420 图框各出一份 + 重复出图一份，全部成功；
- PDF 页数 = 1，MediaBox = 1190.55×841.89 pt（A3 横向），无栅格图片对象；
- 内容流含非灰度颜色算子（红/绿/蓝），人工打开确认图框红色、圆绿色、文字蓝色；
- 出图前后布局打印设置逐字段一致（含设备、介质、纸张单位、范围、窗口、
  比例选项、打印样式开关）；打印引擎状态回到 `NotPlotting`。
