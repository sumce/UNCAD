# UNCAD Pro 2.6.3

发布日期：2026-10-11

本版按用户裁决与审计结论修业务规则一致性问题，并新增 `Ruanguan_GW` 软管块支持。

## 新增

**支持 Ruanguan_GW 等软管块变体。** 同一台设备的软管块在不同项目里存在
`Ruanguan_GW` 这类派生块名，它与 `Ruanguan` 是同一个业务对象。识别改为按块名首段
判定：`Ruanguan`、`Ruanguan_GW`、`Ruanguan-GW`、`Ruanguan$0$` 都算同族，
`RuanguanXYZ` 这种黏连名不算。U1F/U1U/U1C 读长度、写型号与长度、以及三维预览的
软管逻辑因此对两者完全一致（`BlockNameNormalizer.IsFlexibleConduitBlock` 一处实现，
图框选择与 Ruanguan 写入共用）。

## 修复

**1. 两行标注换序后长度泄漏进电缆（D-018）。**

配对只向后扫描：长度行排在标题行之前时不算配对，于是裸长度被计入电缆合计、
桥架/线管本身被静默丢弃（实测 `["2500mm","梯形桥架200Wx100H"]` → 电缆 2.5m、桥架 0）。
现在配对与顺序无关，且还原时始终写成统计认识的"型号 + 长度"。

**2. 无编码的既有插座行把 CAD 与 BOQ 拖成不一致（D-016）。**

既有插座行被无条件标记为"已匹配"，即使它没有固定清单编码：U1F/U1U 会照写进图纸表格，
直到 BOQ 导出阶段才整批中止——那时图纸已经改过。现在读取时与另外两处一样从 NO. 列
回退取编码；确实没有编码的行保持"未匹配"，由 D-016 在 CAD 事务之前拦住，让用户在
清单确认里替换或删除。

**3. 桥架尺寸带尾零导致整条命令中止。**

毫米写法没有复用格数写法的规格规范化，`桥架200.0*100` 会拿 "200.0*100" 去查固定
清单并抛"固定清单中没有桥架规格"。现在两种写法得到同一规格（`桥架200*100`）。

**4. U1Q 可能写出统计读不出来的长度。**

12.5 格 × 250 mm/格 = 3125mm，而统计只认"结尾 0"的长度；写上去这条桥架在下一次
U1F/U1U 里会静默消失。现在写标注前先判可读性，读不出就保留原来的格数写法
（旧写法统计照样认，数据不丢）。

**5. 同一上游类型两套规范化。**

清单规划用精确比较 `I-Line盘`，动态块可见性却用忽略空白/下划线/连字符的规范化，
于是 `Iline盘`、`I-Line 盘` 静默少生成电盘与断路器行。现在两者共用同一套规范化。

## 决策

- **D-028**：U1L 写出的裸毫米标注就是该段电缆长度，**计入** U1U/U1F 电缆统计。
  D-006 的排除范围仅指用户通过 U1LX 另行输入的距离数据，不得据此把 U1L 标注从统计里剔除。
- **D-029**：软管块族包含 `Ruanguan` 及其分隔符派生名（如 `Ruanguan_GW`）。

## 验证

- `dotnet test UNCAD.slnx`：1024 项全部通过（本版新增 23 项回归测试，覆盖顺序反转
  配对、未编码插座行、Ruanguan 块族、桥架规格规范化、可读长度检查、NEXT 写法）。
- 真机自检 `UNCAD_U1Q_SELFTEST`（accoreconsole）PASS——覆盖本版改动的 U1Q 写标注路径。

## 已知红灯（非本版引入，需要先定性）

`UNCAD_TABLE_FILL_SELFTEST` 在 "shipped template" 阶段失败：

```
Generated BOQ row 2 height was 24632.568260319, expected fixed height 5847.8848.
  at TableFillSelfTestCommand.VerifyTemplate(...)
```

也就是说，**出厂的 BOQ 模板第 2 行行高是 D-027 规定值的 4.2 倍**。该自检文件、
行高实现（`TableFillFormatter.GeneratedRowHeight`）与 BOQ 模板在本版均未被改动，
属于既有问题；两种可能：模板文件漂移，或自检断言过期（按模板某种合法形态写的）。
模板是客户可见产物，改动会影响所有新生成的清单表，因此本版只报告、不改动。
