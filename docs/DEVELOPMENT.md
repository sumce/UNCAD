# UNCAD 开发一致性标准

## 模块边界

- `Core`：纯业务契约、解析、匹配、统计和格式化；不得依赖 AutoCAD、WinForms、注册表或进程全局状态。
- `Cad`：AutoCAD 文档、事务、选择集、实体和样式适配；不得包含 Excel 清单匹配规则。
- `Infra`：配置存储、日志、品牌、命令注册和运行时适配；配置键只能定义在 `ConfigKeys`。
- `Features`：编排用户操作；负责读取一次配置快照、调用 Core 规划并在一个事务中提交 CAD 变更。
- `UI`：只编辑传入模型并返回用户决定；不得自行重读 Excel 或扫描图纸。

## 业务模块与排障

| 模块 ID | 模块名称 | 输入 | 输出 | 负责范围 |
| --- | --- | --- | --- | --- |
| `SUM-STAT` | 求和统计 | 清理后的文字行、统计类别、每格毫米数 | 电缆/桥架/线管汇总及来源/命中计数 | 文字规则解析和长度求和，不读取Excel、不写CAD |
| `BOQ-TABLE` | 清单表格 | 机台回路、BOQ索引、求和结果、生成配置 | 默认清单行、评审模型、最终表格写入行数 | 清单规划、匹配状态和CAD表格写入，不计算图纸长度 |
| `U1LX` | 快速标注距离 | 当前空间独立 `Line`、关联毫米标注、端点容差和用户选择 | 逐段命令行输入距离写标注，视角中心自动跳到下一段 | 连接图遍历计划、点击端点分类、中部点击询问方向；Esc 保留已完成部分；不再依赖已移除的 U1X 3D 编辑器 |
| `U1UL` | 毫米标归位 | 带 U1L/U1LX 关联元数据的毫米标及其线段、U1SET 毫米标偏移/位置、选集（线段/毫米标/图框） | 毫米标的新位置与角度 | 纯几何归位规划 `Core/QuickLine/QuickLineLabelPlacement`：只改离线距离和角度，所在侧与沿线位置保持，不改文字和字高；一个事务，任一目标算不出位置整体放弃；`Cad/QuickLine/QuickLineLabelAlignService` |

- 模块必须通过 `ModuleRunner` 执行有外部副作用或可能失败的阶段；日志统一记录模块ID、阶段、耗时和异常。
- 对用户显示的异常格式为 `模块[模块ID/名称]在[阶段]阶段失败`，首先按模块ID定位，不从整个命令入口开始猜测。
- `SUM-STAT`固定拆分为“读取图中文字”和“解析并求和”；`BOQ-TABLE`固定拆分为“规划清单行”和“写入CAD表格”。
- 文件日志按天位于 `%APPDATA%\UNCAD\logs\uncad-YYYYMMDD.log`（2.10.0 起；级别与保留天数在 U1SET →「日志与记录」配置，默认 INFO/30 天）。例如搜索 `MODULE BOQ-TABLE`即可查看表格模块各阶段耗时和失败堆栈。
- 每次命令执行另写一条操作记录到 `%APPDATA%\UNCAD\history\operations-YYYYMM.jsonl`（默认保留 6 个月，U1SET 可查看）：命令、摘要、结果、耗时、机台数、输出文件、线程号；写入失败只记日志，绝不影响命令结果。
- 模块输入应在边界处快照化，输出集合应返回防御性副本；UI编辑不得反向污染规划结果。
- `Manual`只表示“由用户手动加入评审”，不是自定义材料。该行必须由固定清单`ListItem`创建，编码、名称、特征和单位不可自由编辑，只有数量属于本次评审。
- 后续模块使用稳定、可搜索的英文ID，中文名称可以调整但不得复用ID。

### Xauto 自动优化排障（3.2.0）

- 链路：`Features/XAuto/XAutoFeature.cs` 编排 → `Core/QuickLine/SketchProportionPlanner.cs`
  （按 mm 重排+钳位+包络锚定，复用 `QuickLineIsometricSceneBuilder` 重建）→
  `Core/QuickLine/RouteCrossingPlanner.cs`（最终几何交叉检测+深度裁定）→
  `Cad/QuickLine/ArchBridgePolyline.cs`（与 U1R 共享的半圆洞几何）。
- 等测约定：`Core/QuickLine/IsometricProjection.cs` 是 3D→草图的逆映射
  （X=30°/Z=90°/Y=150°），相机深度 = z−x−y（视线零向量 (1,1,−1)），与
  U13D 的场景分类共用同一套轴测方向。
- 整分量跳过的点名原因（未标注/不可分类/包络退化）都出现在命令行报告里；
  语义边界见 `docs/DECISIONS.md` D-053 与 `docs/KNOWN-ISSUES.md` Xauto 一节。

## 注释硬性要求

- 新增模块、公开类型和跨层契约必须有简洁的 `summary`，说明责任边界而不是复述类型名。
- 状态分离、回滚、缓存、兼容和异常分支必须注释“为什么”；禁止只写“设置变量”等无信息注释。
- 业务编排按阶段注释，维护人员应能从入口直接看出检测、求和、规划、评审、清除/写入和完成顺序。
- 修改非显然逻辑时同步更新相邻注释和测试；过期注释与错误代码同等处理。

## U1F / U1U / U1DWG 工作流

1. 检测清单表、图框、设备块、上下游块和统计文字，只读不写。
2. 按实际标注求和电缆、桥架和线管，加载机台/盘柜 Excel 与内嵌固定清单。
3. 生成按类别排序的默认清单；`类`是自动判定的唯一边界，分类内只比较规范化后的`别名`，未命中再按全局唯一`别名1`迁移到该数据库行。空`类`不得通过编号、名称或特征反推。
   `U1SET` 可分别关闭电缆、断路器、电盘、软管、线管、桥架、插座盘和插接箱的自动生成；默认仅关闭插座盘，其余开启。电盘与断路器是不同清单类别，不得共用开关或名称；插座行仍由设备块状态和 D-008 决定，不属于该开关。
4. 用户可修改、增加、删除、取消项目；删除后顺序自动连续，恢复默认可重建自动项。`U1F` 生成保持单图框；`U1U` 对多个 `frame_20260812` 按当前真实外框逐框读取已有身份、统计和表格，统一预检后用一个事务批量更新。
   `U1U` 选中单个图框时会自动扩展到同框对象；电缆按图框属性、现有清单、固定清单顺序匹配，没有新的统计文字时保留电缆/桥架/线管数量，`Ruanguan` 删除则删除软管行；已有插座行的数量和型号不被覆盖。未匹配固定清单的清单项（D-052，2026-11-10 起）在 CAD 写入前集中选择——批量与单图同权：批量预检为**每一个**未匹配项（任意类别、可多条）建替代选择请求，确认后逐项应用；不再只收集电缆/母线插接箱各一条。
5. 清除配置的数据区（默认No.1-No.11），按最终顺序生成新数据。
6. 生成 BOQ/DWG 之前先做**整机回路校验**（2.10.0）：每个机台在快照中的全部回路都必须出现在本次选集中，缺回路时列出缺少项并中止，图纸与 BOQ 都不修改；`UNC_FILL_REQUIRE_ALL_CIRCUITS=0` 可关闭。D-044（2026-11-03）：U1F 缺回路与 U1U 同口径——图框照常填写、只跳过该机 BOQ，补全后执行 `U1S` 补清单；U1S/U1DWG 保持硬门禁。D-043（2026-11-03，3.2.0.4 修订）：候选=**水平·单行·整数以 0 结尾且必须 mm 后缀**（`3000mm` ✓、`3000`/`555mm`/小数/多行 ✗）；**U1F 无条件吸收并删除标注**（重新定义），**U1U 复制框（外来 JSON）不吸收不删除只从统计排除**，多处候选一律不自动取值（`UNC_FILL_DEVICE_RESERVE_AUTO` 默认开）。  
   表格和全部块属性在一个事务中提交；异常整体回滚。事务提交后立即读取实际 CAD 结果，并按机台写入 `<输出根>\机台ID\[BOQ]机台ID.xlsx`（D-042：BOQ/DWG/PDF 同一个机台文件夹，无图纸/类别分层；默认输出根为 `我的文档\UNCAD输出`）。BOQ 写入失败不回滚已提交的图纸：命令行与弹窗必须明确要求重跑 `U1S` 重新导出清单，本批 BOQ 文件本身仍按批次恢复为修改前的版本。BOQ 仅更新固定模板项目编码对应的工程量列。`U1DWG`复用同一图框分区和身份读取，按机台输出 `<输出根>\机台ID\机台ID.dwg`（与 BOQ/PDF 同夹），同机台设备框横向排列且间距为 10000；首个图框作为保存视图中心，左侧写入机台ID、品牌、生成时间、软件版本和 Windows 用户。

设备原电缆型号与清单替代型号是两个字段。替代型号只更新 `BOQ-TABLE` 行，不得修改图框/块属性；自动 Excel 记录同时保存两者和完整材料明细。

### 图框与 frameinfo_json（v2 / D-040）

- 当前模板只有动态块 `FRAME_20261119`（2026-11-19 用户模板）；旧 `FRAME_20261102` / `xframe_v2` / `frame_20260812` / `frame` / `xframe` 仍可读，U1F/U1U 首次写入时自动迁移到当前定义，保留同名属性值、补充新属性并移除新定义里不存在的旧属性。`INFO2` 是单行属性，只显示桥架和刚性线管；型号与毫米长度以空格分隔，例如 `镀锌穿线管38mm 4000mm`，多段长度如 `2000 +2500 = 4500mm`。软管仍由独立 Ruanguan 块更新，不进入 `INFO2`。U1U 仅对测量未知的桥架/线管类别保留旧段，并清除遗留软管段。旧 `CONDUIT_INFO` 属性（若存在）沿用兼容格式；BOQ 与统计报表单位不变。
- JSON 主存储是**图框块自身的 `FRAMEINFO` 文字属性**（D-040）：元数据随图框实体走，复制/移动零丢失，不存在几何归属；图框缺该属性引用时写入方从块定义补建。独立 `frameinfo_json` 块与旧内嵌 `FRAMEINFO_JSON` 属性降级为遗留读源：读取照常，首次写入后清空属于本框的遗留副本，不再新建独立块。v2 结构为 `identity/upstream/downstream/cable/drawing/meta/changes` 的嵌套文档，所有键必出，`changes` 最多 20 条，整份 JSON 上限 6000 字符；超限先裁最旧 history，仍超限必须中止写入而不是写截断 JSON。旧 v1 扁平 JSON 仍可解析用于迁移。
- `meta.frameHandle`（2.11.0-dev 起）把记录绑到图框句柄；身份读取在 JSON 与图框物理标注分歧时信物理标注（仲裁），他机遗留记录不参与继承——这三道闸是遗留源的兼容层，新存储下自然满足。D-052（2026-11-10）：句柄失配时先做**搬场重绑判定**——记录身份与本框当前物理身份一致、且记录的原句柄不再指向本图一个仍带图框属性的块参照（撞上同号无关实体不算，3.0.0.14）→ 判定搬场（跨文件复制/移动整机台），收下记录（预留/替代/历史）并在下次写入时重盖句柄；原句柄仍指向活的图框块（同文件复制）或身份不符（改号/幽灵）→ 维持外来拒绝 + 清理（3.0.0.6/3.0.0.8/3.0.0.9 语义不变）。复制图框的设备内预留不做静默恢复，但 CABLE_INFO 里可解析的「数值（设备内）」作为**预填建议值**带出（批量弹窗预填行 + 来源标注列，单图清单确认窗预填），用户核对确认。复制框的显式清理（ClearStaleInfo）必须**先于 FillFrame**（3.0.0.14 修正：3.0.0.9–13 的先写后清把刚写入的 CABLE_INFO/CONDUIT_INFO 一并抹空，复制框电缆信息永远为空），且复制框的 FillFrame **不走 U1U「保留旧值」标志**（3.0.0.16：旧值刚被清空，保留保住的是空串；复制框一律按 U1F 口径现算现写）。**3.2.0.4（D-052 附录7）：U1F=重新定义——每次运行都无条件清旧属性（不再限于复制框）、不复用旧记录、不做恢复兜底/复制源预填、遗留独立块记录也不继承（3.2.0.5）；U1U 仍仅复制框清。**随框带过来的横排毫米标同属源框残留：**D-043 的复制框守卫（不吸收、不删除图上文字，但仍从米数统计排除——"3000mm"同时命中电缆长度判据，不排除会双算）现仅 U1U**；U1F 对横排 0mm 标无条件吸收并删除。U1F 改选机台（复制改号/换机台重定义）时，`FrameRedefineGuard`（3.0.0.17，机台选定后、电缆预留解析前——3.2.0.4 起预留/吸收阶段先行执行、守卫接线在其后；单框与批量预检两链都接线，批量侧 3.2.0.6 补齐幽灵记录防御）把旧 JSON 记录与 CABLE_INFO 建议值整体丢弃——它们属于图框原来的那台机；同机台（重跑 U1F/同机台第二只框/跨文件搬场）不受影响。**3.2.0.4 后该守卫在 U1F 上为提示性（记录/建议值已在预留阶段先行复位）；空机台号吸收记录（D-043 产物）是会话合成，同机/改机两分支都保留（3.2.0.5 审计修复）。**
- `cable` 段保存 `measuredM`（图上实测）、`panelReserveMm`（按上游类型）、`deviceReserveMm`（用户确认）、`totalM`。U1F/U1U 电缆总长 = 实测 + 盘内/箱内预留（I-Line 盘 3400 盘内 / 插座盘 1000 盘内 / 母线插接箱 500 箱内）+ 设备内预留 + 业主统一预留（默认 3000，U1SET 可改）。设备内预留不在命令行询问，而是在清单确认窗口/GUI 中填写：首次默认 0，用户可改，确认后写入 JSON，后续自动预填。CABLE_INFO 必须全部用 mm，型号直接显示工程前缀（不加“电缆”二字），明细统一写成 `数值（说明）` 并用 + 连接，最后 `=总长mm`；例：`ZB-YJVR-5*4mm²: 1000 +700 +3400（盘内） +2000（设备内） +3000（预留）=…mm`。旧属性中的“电缆”前缀仍可读取。段与段之间是**空格+加号**（` +`，3.0.0.15）：MText 只能在空格/汉字处断行，`1000+5400+…` 纯数字串是一整个不可断词，段数一多整串下移、首行只剩型号；空格断点让型号与数字同排一行、行数最少。不再出现中间的 `=实测合计`，也不再出现 `=26.2M` 这类米制写法；某一类预留为 0 时对应段落直接省略。CABLE_INFO 是**多行属性**，写入时必须把 MText 文本框宽度设为 **78300** 图形单位，让 AutoCAD 自动换行；读回方只认「数值（设备内）」紧贴结构与型号前缀，旧版无空格写法仍可解析。

- `meta.filledUtc` / `meta.lastCommand`（3.6.0，D-057）：最近一次 U1F 的时间（U1F 是重定义模式，每次重盖；U1U 沿用）与最近一次写入的命令（`U1F`/`U1U`）。制图信息表（图框内小表）六列内容来自 U1SET 模板（`UNC_FILL_INFO_*`，`Core/Fill/DrawingInfoTemplate`）：留空 = 不写该格；`(U1F创建时间)` 读 `filledUtc`，`(U1U更新时间)` 只在 `lastCommand == "U1U"` 时有值。写表与写 JSON 的时间取法同源（`FrameInfoJsonRecordUpdater.ResolveFilledUtc` / `DrawingInfoContext.ForRun`）。老 JSON 无这两个键，按空串读，U1U 接手时把原 `updatedUtc` 当创建时间。

- CABLE_INFO display amendment (3.4.1.9): newly written values prefix the
  model with `电缆 `; this supersedes the earlier no-label format note above.
  Both prefixed and unprefixed legacy values remain readable.

## 代码契约

- 命令开始后使用不可变运行时配置快照；预览和最终写入必须使用同一份参数。
- `ManualListItemForm` 清单选择坚持用户视角：顶部类别标签、连续添加、分词搜索、最近使用置顶；未匹配项替换必须自动定位并锁定原类别，禁止把桥架身份替换进电缆行。新增 UI 记忆键必须走 `ConfigKeys`，且写入路径不得依赖 AutoCAD 主机（测试宿主无 AutoCAD）。
- 固定清单以`Resources/embedded_catalog.tsv`内嵌进程序集，用户唯一需要提供的Excel是机台/设备表。改清单源表后必须重新运行`scripts/GenerateEmbeddedCatalog.ps1`、重新生成资源并升级插件版本，禁止让用户提供清单文件。内嵌 TSV 出现列数、编码或名称缺失时必须立即失败，禁止静默丢行。
- 主别名采用精确类别和精确值匹配，不得用相邻直径或相似名称替代；只有数据库显式填写的全局唯一`别名1`可以迁移到其所在行。
- 机台/设备表读取失败必须区分 IO 占用与格式/解析错误：读取路径只对瞬时 IO 失败重试，其他异常立即保留原始类型和堆栈，避免把坏文件误报为“正在更新”。
- 常见等价输入可先规范化，例如 `DN32`、`Φ32`、`32mm` 均规范为 `32`；规范化不等于型号替代。
- 未匹配条目必须禁用且不得进入`SelectedRows`；用户取消勾选的固定清单条目也不得进入最终写入，即使取消后立即确认。只能替换为固定清单数据库项目或删除，不存在空编码确认生成。
- 所有外部输入必须处理空值、非法数值、溢出和范围；不得通过异常控制正常分支。
- 用户取消返回时不得写图、保存配置或创建提交文件。

### U1LX 实机验收

1. 用 `U1L` 按 30°、90°、150° 绘制 5--8 段端点相连的独立 `Line`，确认每段都有唯一毫米 `DBText`；另画一根只在中部交叉的线。
2. 执行 `U1LX` 或 `UNLX` 并选择任意一段，确认窗口只载入该端点连通分量，交叉但端点不相接的线不得串入。
3. 逐段输入正数毫米并回车；确认每次写入后视图中心跳到下一条连通线，直接回车保留当前值，Esc 保留已完成部分。
4. 点击线段端点时从对应端开始；点击中部时确认方向询问只影响本次遍历，端点容差范围内的线段可连通，交叉但端点不相接的线段不得串入。
5. 至少输入一次真实的 `2000mm`；对带 U1L 关联的复合文字确认只替换唯一 `mm` 数值且保留前后说明。

## AutoCAD 写入

- 同一业务动作中的表格和块属性变更必须共享一个数据库事务；任一未处理异常整体回滚。
- 写入前完成目标数量、表格容量、配置范围和必填字段验证。
- `UNC_CONDUIT` 线管标注固定使用 `2000mm` 人工占位，不得传入曲线实测长度；退化曲线必须在实体入库前预检并单独跳过。
- U1Q/U1C 连续段按端点连通自动合并为一趟（D-050）：偏移线必须走解析式 miter 构建
  （`OffsetPolylineBuilder`，构造上不翻侧），不得回退 `GetOffsetCurves` 直出；
  U1Q 标注长度初值 = 成员 U1L 毫米标合计（无标签段用几何长度）取整到 10，
  U1C 维持 2000mm 占位不变。
- 禁止通过命令字符串实现可直接使用数据库 API 的几何或编辑操作。
- 不得关闭、保存或替换用户图纸；自动化验收只能使用临时图形或只读检查。

## Excel 与性能

- 机台数据必须由用户选择工作簿（本地/UNC 文件或 HTTP/HTTPS 网络地址，D-041 只下载）；本地与网络源都只在 `U1DATA` 或 `U1SET` 的"刷新"按钮处显式刷新，启动时不自动联网。读取器只接受统一 `U_` 字段和普通 `回路名称`，不允许 A1/A2、旧字段或备用字段回退。刷新时将解析结果写入 SQLite 快照，U1F/U1U/XSTS/XLAYOUT 等业务命令不得下载或重新解析源文件。
- SQLite 快照查询返回新的 `MachineRow` 对象，调用方不得修改数据库值；机台/回路查询应按需读取，避免每次命令把整个工作簿载入内存。快照写入使用事务，解析或写入失败时保留上一次有效快照。
- 固定清单是程序集内只读资源，不参与外部文件缓存；一次填充只创建一个 BOQ 索引。
- 机台工作簿刷新走 SQLite 快照流程，不得在命令入口复制一套自动重读逻辑。
- 提交工作簿写入前后必须验证内容指纹；检测到外部修改、写锁或并发创建时停止覆盖并保留原文件。

## WPF Layout（3.8.0 起）

- 业务窗口全部是 WPF/FluentKit；WinForms 旧窗体基础设施（`UiKit`、`DialogLayout`、
  `BrandMarkControl`）已在 3.8.0 结构清理中删除，不得重新引入。
- 仍保留的 WinForms 只用于 `FolderBrowserDialog`/`Screen`/窗口句柄等系统互操作，
  不承载布局或业务控件。
- 可增长内容使用 WPF 布局容器、百分比列和明确最小宽度；禁止只依赖固定像素宽度。
- 数值配置使用有范围的 `NumericUpDown`；禁止用文本框解析失败后静默回退。
- 校验失败时切换到对应页签、聚焦字段并保留用户输入。
- 警告描述当前状态和下一步动作；危险或未匹配写入必须由用户明确确认。

## 复用与依赖方向

- 共享能力必须先进入已有边界：纯规则放入 Core，AutoCAD 适配放入 Cad，跨命令运行时策略放入 Infra，窗口只放在 UI；禁止在 Feature 之间复制业务实现。
- Feature 只负责编排：选择、配置快照、调用共享服务、预检、事务和用户反馈。相同输入必须调用同一个服务，不得为 U1U、U1S、U1DWG 和 XLAYOUT 各写一套图框识别或身份读取。
- 图框识别统一使用 FrameRegionCollector；图框身份统一使用 FrameIdentityReader（目标归属 `Cad/Frame`，见 `docs/ARCHITECTURE.md`）；文件批次恢复统一使用 FileBatchRollback；命令文档统一使用 CommandHelpCatalog。
- 层、模块、共享能力的唯一清单与迁移顺序见 `docs/ARCHITECTURE.md`；本节只保留工程规则，不重复结构决策。
- 共享服务必须是无 UI 的可测试 API；UI 不得被 Core/Cad 反向依赖。需要显示的内容通过模型返回，不能在底层弹窗。
- 新增公共类型必须说明责任边界、输入约束、失败行为和线程/事务要求；重复三次以上的稳定逻辑必须评估抽取，但不得为了减少行数制造无语义的万能工具类。
- 命令、Ribbon、Bundle、帮助页面和测试必须从同一个命令注册契约校验；新增命令不得只改某一处清单。
- 每个发布版本在更新记录中拥有独立页面；升级提示只列出未读版本，`U1A` 必须保留全部历史版本的详情入口。

## AutoCAD 真机自检（accoreconsole）

CAD 行为不能只靠纯单测；出图、写图这类必须真机验证：

- 脚本：`tests/UNCAD.CadIntegration/run.ps1 -Command <命令> [-InputDrawing <dwg>]`。
  它把图纸复制到临时目录，用 `accoreconsole.exe /i /s` 跑 `NETLOAD` + 自检命令，
  自检命令把 `PASS`/`FAIL` 写到 `%UNCAD_CAD_INTEGRATION_RESULT%`。
- **必须先 `SECURELOAD 0`**：否则 AutoCAD 会"加载成功但不注册命令"，脚本里只会看到
  "未知命令"。`run.ps1` 已默认带上这一步。
- `UNCAD_U1PDF_SELFTEST`（出图内核）：真机出图后逐项断言——页数 ≥ 1、
  MediaBox = A3 横向（1190.55×841.89 pt）、PDF 内容流里有**非灰度**颜色算子、
  出图**不改动**用户布局打印设置、结束后打印引擎回到 `NotPlotting`。
  2.10.0 起还覆盖"同一目标路径重复出图"：真实 PlotEngine 会覆盖旧 PDF（实测 AutoCAD 2022
  不需要先删文件），自检把旧文件改成哨兵文本后再出图并校验 `%PDF-`，防止重跑同一批时静默失败。
  `%UNCAD_PLOT_KEEP_DIR%` 可保留产出的 PDF，`%UNCAD_PLOT_PROBE_DUMP%` 保留诊断文本。
- `UNCAD_PLOTPROBE`（打印 API 探针）：复核 AutoCAD 打印接口的坑，
  例如**窗口区域必须先于 `SetPlotType(Window)`**、以及用
  `PlotInfo.OverrideSettings` 时校验器会把请求的介质换成布局自带的那一份。
- `UNCAD_TXPROBE`（事务语义探针）：验证"不 `Commit` 直接 `Dispose`（或 `Abort`）
  是否真的回滚"。U1PDF 失败路径靠回滚丢弃临时打印设置，这条修复的全部正确性都
  建立在该前提上；探针同时用 `Commit` 作对照，避免出现"什么都没变"的假通过。
  结论（AutoCAD 2022 实测）：`Dispose` 未提交 = 回滚，`Commit` = 落盘。
- `UNCAD_ROUTE_PREVIEW_SELFTEST`（3.7.0 / 3.8.0，U1U 3D 预览数据链）：在
  `XFrameTemplate.dwg` 上画三段带毫米标的路线（一处拐角差 30）、一条无毫米标的
  线、一趟带元数据的桥架输出、一条 U1B 软管标注、两个块引用、一个没有归属的
  毫米标和一个设备预留标记形态的横排数字，走真实的体检 + 预览构建，断言断口
  接上、桥架整趟（趟数 + 整趟长度）、两端落在离连接块最近的末端、软管取 U1B
  标注长度、楼层平面与跨层高度报警、上游柜落地、无归属毫米标与缺失轴位块点名
  （预留标记不点）、场景里没有华夫板；3.8.0.1 起楼层平面是线框（不再有半透明面）；
  3.8.0.3 起跨层报警量的是「上游楼层地面到设备端」（I-Line 盘：线路竖向；插座盘：
  离地 1 m + 线路竖向），文案点名 U1SET 标高清单的来源条目。
- `UNCAD_LABEL_ALIGN_SELFTEST`（3.7.0 / 3.8.0，U1UL 毫米标归位）：真事务里断言
  归位后所在侧/沿线位置/文字/字高/关联元数据不变；没有毫米标的线段计数、
  只靠位置匹配（贴在线旁）的毫米标也归位但不补写关联、离线太远的那个不动并
  计数；重跑幂等。
- `UNCAD_LEGACY_TRAY_SELFTEST`（3.8.0.1，旧图框桥架）：竖排多行文字
  「梯形桥架200Wx100H / 3500mm」+ 缩短红线 + 没有归属元数据。断言扫描器不把
  第二行的 3500mm 当电缆毫米标、红线拆段找到旁边带毫米标的电缆、整趟 3.5m、
  红线算标注线且不再报「没有毫米标」/「找不到宿主」。3.8.0.3 起加单行写法
  「梯形桥架200Wx100H-1300mm」（长度 1.3m、宽度按「宽Wx高H」读，不再报
  「毫米标没有归属线段」），宽度不再是缺省值。
- `UNCAD_CURVE_ROUTE_SELFTEST`（3.8.0.1，非 LINE 电缆段）：闭合但顶点共线的

  电缆毫米标。
- `UNCAD_BENT_POLYLINE_SELFTEST`（3.8.0.2，一笔画出的路线）：开口无弧、每腿
  都在制图轴上的多段线（斜 3400 / 竖 2000 / 斜 3000，两个标注带指向它的旧
  关联）在填充/U1U 口径下拆成 3 段（键＝句柄/序号）、各有标注、无归属为 0、
  3D 里三段都在；默认 U1LX 口径不拆；带斜腿的绕行多段线不拆。
- `UNCAD_DUMP_HANDLES`（只读诊断，不是门禁）：按句柄导出实体的真实几何

## 代码评审门槛

- 先证明需求和实体模型，再实现；不得根据名称猜测 AutoCAD 实体类型或把独立实体强行转换为其他类型。
- 任何 CAD 写入必须明确事务所有权、提交点、取消行为和失败后的用户可恢复状态。
- 文件输出必须说明覆盖策略、并发/锁处理、批量失败恢复和备份生命周期；禁止静默降级为可能破坏原文件的覆盖。
- 业务规则、文件 IO、AutoCAD API 和 WinForms 不得混在一个方法中；超过一个职责的入口必须拆成可单测服务。
- 测试优先验证公开行为和边界；源码字符串契约只能验证注册元数据，不能替代 CAD、文件和 UI 行为测试。
- 每个新命令提交前必须完成：命令注册测试、Core 规则测试、至少一个失败分支测试，以及 AutoCAD 宿主手工验收记录。

## 验证门槛

- 每个解析/匹配规则必须有纯 Core 单元测试。
- 每个配置字段必须有默认值、边界和持久键测试。
- 主要窗口必须覆盖 DPI、最小尺寸、关键控件和动态联动。
