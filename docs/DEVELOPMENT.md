# UNCAD 开发一致性标准

## 模块边界

- `Core`：纯业务契约、解析、匹配、统计和格式化；不得依赖 AutoCAD、WinForms、注册表或进程全局状态。
- `Cad`：AutoCAD 文档、事务、选择集、实体和样式适配；不得包含 Excel 清单匹配规则。
- `Infra`：配置存储、日志、品牌、命令注册和运行时适配；配置键只能定义在 `ConfigKeys`。
- `Features`：编排用户操作；负责读取一次配置快照、调用 Core 规划并在一个事务中提交 CAD 变更。
- `UI`：只编辑传入模型并返回用户决定；不得自行重读 Excel 或扫描图纸。

## 业务模块与排障

| 模块 ID | 模块名称 | 输入 | 输出 | 负责范围 |
| --- | --- | --- | --- | --- |
| `SUM-STAT` | 求和统计 | 清理后的文字行、统计类别、每格毫米数 | 电缆/桥架/线管汇总及来源/命中计数 | 文字规则解析和长度求和，不读取Excel、不写CAD |
| `BOQ-TABLE` | 清单表格 | 机台回路、BOQ索引、求和结果、生成配置 | 默认清单行、评审模型、最终表格写入行数 | 清单规划、匹配状态和CAD表格写入，不计算图纸长度 |

- 模块必须通过 `ModuleRunner` 执行有外部副作用或可能失败的阶段；日志统一记录模块ID、阶段、耗时和异常。
- 对用户显示的异常格式为 `模块[模块ID/名称]在[阶段]阶段失败`，首先按模块ID定位，不从整个命令入口开始猜测。
- `SUM-STAT`固定拆分为“读取图中文字”和“解析并求和”；`BOQ-TABLE`固定拆分为“规划清单行”和“写入CAD表格”。
- 日志默认位于 `%APPDATA%\UNCAD\logs\uncad.log`。例如搜索 `MODULE BOQ-TABLE`即可查看表格模块各阶段耗时和失败堆栈。
- 模块输入应在边界处快照化，输出集合应返回防御性副本；UI编辑不得反向污染规划结果。
- `Manual`只表示“由用户手动加入评审”，不是自定义材料。该行必须由固定清单`ListItem`创建，编码、名称、特征和单位不可自由编辑，只有数量属于本次评审。
- 后续模块使用稳定、可搜索的英文ID，中文名称可以调整但不得复用ID。

## 注释硬性要求

- 新增模块、公开类型和跨层契约必须有简洁的 `summary`，说明责任边界而不是复述类型名。
- 状态分离、回滚、缓存、兼容和异常分支必须注释“为什么”；禁止只写“设置变量”等无信息注释。
- 业务编排按阶段注释，维护人员应能从入口直接看出检测、求和、规划、评审、清除/写入和完成顺序。
- 修改非显然逻辑时同步更新相邻注释和测试；过期注释与错误代码同等处理。

## UNC_F / UNC_UPDATE 工作流

1. 检测清单表、图框、设备块、上下游块和统计文字，只读不写。
2. 按实际标注求和电缆、桥架和线管，加载机台/盘柜 Excel 与内嵌固定清单。
3. 生成按类别排序的默认清单；`类`是自动判定的唯一边界，分类内只比较规范化后的`别名`，未命中再按全局唯一`别名1`迁移到该数据库行。空`类`不得通过编号、名称或特征反推。
4. 用户可修改、增加、删除、取消项目；删除后顺序自动连续，恢复默认可重建自动项。`UNC_F` 生成保持单图框；`UNC_UPDATE` 对多个 `frame_20260812` 按当前真实外框逐框读取已有身份、统计和表格，统一预检后用一个事务批量更新。
5. 清除配置的数据区（默认No.1-No.11），按最终顺序生成新数据。
6. 表格和全部块属性在一个事务中提交；异常整体回滚。事务提交后立即读取实际 CAD 结果并自动更新 `UNCAD_Submissions.xlsx`。

设备原电缆型号与清单替代型号是两个字段。替代型号只更新 `BOQ-TABLE` 行，不得修改图框/块属性；自动 Excel 记录同时保存两者和完整材料明细。

## 代码契约

- 命令开始后使用不可变运行时配置快照；预览和最终写入必须使用同一份参数。
- `ManualListItemForm` 清单选择坚持用户视角：顶部类别标签、连续添加、分词搜索、最近使用置顶；未匹配项替换必须自动定位并锁定原类别，禁止把桥架身份替换进电缆行。新增 UI 记忆键必须走 `ConfigKeys`，且写入路径不得依赖 AutoCAD 主机（测试宿主无 AutoCAD）。
- 固定清单以`Resources/embedded_catalog.tsv`内嵌进程序集，用户唯一需要提供的Excel是机台/设备表。改清单源表后必须重新运行`scripts/GenerateEmbeddedCatalog.ps1`、重新生成资源并升级插件版本，禁止让用户提供清单文件。内嵌 TSV 出现列数、编码或名称缺失时必须立即失败，禁止静默丢行。
- 主别名采用精确类别和精确值匹配，不得用相邻直径或相似名称替代；只有数据库显式填写的全局唯一`别名1`可以迁移到其所在行。
- 机台/设备表读取失败必须区分 IO 占用与格式/解析错误：`StableFileCache` 只对 IO 失败重试，其他异常立即保留原始类型和堆栈，避免把坏文件误报为“正在更新”。
- 常见等价输入可先规范化，例如 `DN32`、`Φ32`、`32mm` 均规范为 `32`；规范化不等于型号替代。
- 未匹配条目必须禁用且不得进入`SelectedRows`；用户取消勾选的固定清单条目也不得进入最终写入，即使取消后立即确认。只能替换为固定清单数据库项目或删除，不存在空编码确认生成。
- 所有外部输入必须处理空值、非法数值、溢出和范围；不得通过异常控制正常分支。
- 用户取消返回时不得写图、保存配置或创建提交文件。

## AutoCAD 写入

- 同一业务动作中的表格和块属性变更必须共享一个数据库事务；任一未处理异常整体回滚。
- 写入前完成目标数量、表格容量、配置范围和必填字段验证。
- `UNC_CONDUIT` 线管标注固定使用 `2000mm` 人工占位，不得传入曲线实测长度；退化曲线必须在实体入库前预检并单独跳过。
- 禁止通过命令字符串实现可直接使用数据库 API 的几何或编辑操作。
- 不得关闭、保存或替换用户图纸；自动化验收只能使用临时图形或只读检查。

## Excel 与性能

- 机台数据按规范化完整路径和 SHA-256 内容指纹缓存；文件改变必须自动失效，不能只依赖大小和时间戳。
- 缓存返回防御性副本，调用方不得修改缓存原值；不同文件的加载和重试不得互相阻塞。
- 固定清单是程序集内只读资源，不参与外部文件缓存；一次填充只创建一个 BOQ 索引。
- 文件稳定读取和重试统一使用 `StableFileCache<T>`，不得复制重试循环。
- 提交工作簿写入前后必须验证内容指纹；检测到外部修改、写锁或并发创建时停止覆盖并保留原文件。

## WinForms Layout

- 主窗口使用 `DialogLayout`，启用 `AutoScaleMode.Dpi`，并提供可用最小尺寸。
- 可增长内容使用 `Dock`、百分比列和明确最小宽度；禁止只依赖固定像素宽度。
- 数值配置使用有范围的 `NumericUpDown`；禁止用文本框解析失败后静默回退。
- 校验失败时切换到对应页签、聚焦字段并保留用户输入。
- 警告描述当前状态和下一步动作；危险或未匹配写入必须由用户明确确认。

## 验证门槛

- 每个解析/匹配规则必须有纯 Core 单元测试。
- 每个配置字段必须有默认值、边界和持久键测试。
- 主要窗口必须覆盖 DPI、最小尺寸、关键控件和动态联动。
- 正式版与临时授权版都必须通过完整测试、包清单校验和 SHA-256 产物校验。
- 发布版本使用唯一 ProductCode、稳定 UpgradeCode，并保持 AutoCAD 2022 / net48 / x64 兼容。
- 安装器必须恢复可验证的中断备份，回滚失败必须作为致命错误报告；禁止记录未经验证的“已恢复”。
- 发布脚本必须验证构建输出与 bundle DLL 的 SHA-256 一致；`-NoBuild` 必须拒绝比 DLL 更新的源文件。
