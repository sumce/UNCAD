# UNCAD v1.9.0 发布审计

## Git 提交分析

审计范围为 `v1.8.3` 至 `main@460cd0a`：

| 版本/提交 | 变更 | 审计结论 |
| --- | --- | --- |
| `f685bab` / v1.8.3 | 固定清单选择器重构 | UI 功能增加较多，但未建立完整发布级回归门槛。 |
| `1eb7177` / v1.8.4 | 机台 Excel 重试 | 将非 IO 解析异常误归类为文件更新的风险未被覆盖。 |
| `6535d4f` / v1.8.5 | UNC_SUBMIT 无明细诊断 | 改进了提示，但提交文件并发保护和外部修改检测仍不足。 |
| `c671597` / v1.8.6 | WinForms IME 初始化 | 修复宿主竞争，但发布仍依赖后续安装器补丁。 |
| `4d40ab2`、`460cd0a` | 安装器锁定、回滚、BOM | 回滚失败可被误报成功，中断恢复与陈旧构建门禁缺失。 |

连续小版本的共同问题不是单一功能，而是文件系统、宿主、发布和用户工作流没有作为一条完整链路验证。v1.9.0 将这些问题纳入同一发布门槛。

## v1.9.0 改进

- `StableFileCache<T>` 使用按路径同步和 SHA-256 内容指纹；不同机台文件互不阻塞，格式错误不再伪装为占用或更新。
- 内嵌固定清单严格校验 7 列、项目编码和项目名称，坏资源直接阻止填充，不再静默丢行。
- `UNC_FILL` 容量预检与实际写入复用同一表头定位规则，避免预检行和写入行偏移。
- 设备块动态属性写入失败不再静默继续；异常向上传播并使表格、图框和设备块在同一事务中整体回滚。
- `SubmissionWorkbookWriter` 在读取前后校验内容指纹，拒绝覆盖外部修改，并为不支持 `File.Replace` 的文件系统提供可回滚替代路径。
- 安装器恢复遗留的 staging/backup，区分权限失败和文件占用，且回滚失败必须明确中止。
- 发布脚本校验源文件时间、构建输出和 bundle SHA-256，阻止 `-NoBuild` 打包陈旧 DLL。
- 清理外部固定清单配置和特定办公软件占用假设；用户只提供机台/设备 Excel。

## 验证门槛

- Release 构建：零错误、零警告。
- 单元与回归测试：正式版全量通过。
- PackageContents、DLL 版本、依赖文件和 SHA-256 校验通过。
- Windows PowerShell 5.1 脚本解析与 UTF-8 BOM 校验通过。
- AutoCAD 2022 `accoreconsole.exe` 实际 NETLOAD、初始化和命令注册通过。
- 正式版和临时授权版分别构建、测试、打包和校验。
